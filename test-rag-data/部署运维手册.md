# 部署运维手册

## 一、环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Docker | 20.10+ | 容器运行时 |
| Docker Compose | v2+ | 编排工具 |
| MySQL | 8.0 | 业务数据库 |
| Redis | 7.0 | 缓存与会话存储 |
| Node.js | 18+ | 前端构建（如需本地开发） |
| Python | 3.12 | 后端运行时 |

## 二、快速部署（Docker Compose）

### 2.1 开发栈部署

```bash
# 进入项目目录
cd AgentChat-main

# 启动所有服务
cd docker && docker compose up -d

# 查看服务状态
docker compose ps

# 查看后端日志
docker compose logs -f backend
```

开发栈的服务组成：
- backend：FastAPI 后端，端口 7860
- frontend：Vue 前端（Nginx），端口 80
- mysql：数据库，端口 3306
- redis：缓存，端口 6379
- minio：对象存储，端口 9000

### 2.2 生产栈部署

生产栈与开发栈的区别：
- 配置文件以只读卷挂载（而非 COPY 进镜像），修改后只需 restart 无需 rebuild
- 需要准备 docker_config.prod.yaml 配置文件（从 template 生成）
- 建议使用外部 MySQL 和 Redis，而非容器内置

```bash
# 生成生产配置
cp docker/docker_config.prod.template.yaml docker/docker_config.prod.generated.yaml
# 编辑 generated.yaml，填入真实的 API Key 和数据库连接信息

# 启动生产栈
docker compose -f docker/docker-compose.prod.yml up -d
```

## 三、配置文件说明

### 3.1 config.yaml 结构

```yaml
server:          # 服务配置（端口、环境）
mysql:           # 数据库连接
redis:           # 缓存连接
multi_models:    # 多模型配置
  conversation_model:   # 对话模型
  tool_call_model:      # 工具调用模型
  reasoning_model:      # 推理模型
  text2image:           # 文生图模型
  qwen_vl:              # 视觉模型
  embedding:            # 向量化模型
  rerank:               # 重排序模型
rag:            # RAG 参数
  retrival:     # 检索参数（top_k, min_score）
  split:        # 切分参数（chunk_size, overlap_size）
  vector_db:    # 向量库配置
storage:        # 对象存储配置（MinIO）
```

### 3.2 配置加载机制

后端通过 `agentchat/settings.py` 加载配置：
1. `init_app_settings()` 在 FastAPI lifespan 中被调用
2. 读取 config.yaml 并用 Pydantic 模型校验
3. 校验通过的字段写入 `app_settings` 全局单例
4. 业务代码通过 `app_settings.multi_models.xxx` 访问配置

注意：如果 config.yaml 解析失败，`multi_models` 和 `rag` 会保持默认值 None，此时所有依赖这两个配置的功能（包括 RAG 和对话）都会报错。

## 四、常见运维操作

### 4.1 重启服务
```bash
cd docker
docker compose restart backend    # 重启后端
docker compose restart frontend   # 重启前端
docker compose down               # 停止所有服务
docker compose up -d              # 启动所有服务
```

### 4.2 修改配置后生效

开发栈（config.yaml 是 COPY 进镜像的）：
```bash
cd docker
docker compose up -d --build backend   # 需要 rebuild
```

生产栈（config.yaml 是挂载的）：
```bash
cd docker
docker compose -f docker-compose.prod.yml restart backend   # 只需 restart
```

### 4.3 查看数据库
```bash
# 进入 MySQL 容器
docker exec -it agentchat-mysql mysql -uroot -p123456 agentchat

# 查看知识库
SELECT * FROM knowledge;

# 查看知识库文件
SELECT * FROM knowledge_file;

# 查看 Agent 的知识库绑定
SELECT id, name, knowledge_ids FROM agent;
```

### 4.4 查看向量库
```bash
# 进入后端容器
docker exec -it agentchat-backend bash

# 查看 ChromaDB 数据
python -c "
from agentchat.services.rag.vector_stores.chroma import ChromaVectorStore
# 具体查看方法取决于实现
"
```

## 五、网络与代理配置

### 5.1 容器访问外部 API

如果容器需要通过代理访问外部 API（如 DashScope），在 docker-compose.yml 中为服务添加环境变量：

```yaml
services:
  backend:
    environment:
      - HTTPS_PROXY=http://host.docker.internal:<代理端口>
      - HTTP_PROXY=http://host.docker.internal:<代理端口>
      - NO_PROXY=localhost,127.0.0.1,mysql,redis,minio
```

注意事项：
- `host.docker.internal` 在 Docker Desktop 上可用，Linux 需额外配置
- `NO_PROXY` 必须包含内部服务名（mysql、redis、minio），否则内部通信也会走代理导致失败
- 代理软件需开启"允许局域网连接"，否则容器通过宿主机 IP 访问会被拒绝

### 5.2 前端代理配置

前端开发时的 API 代理在 vite.config.ts 中配置：
```typescript
proxy: {
  '/api': {
    target: 'http://localhost:7860',
    changeOrigin: true
  }
}
```

生产环境中前端 Nginx 直接反代后端，无需额外配置。

## 六、备份与恢复

### 6.1 数据库备份
```bash
docker exec agentchat-mysql mysqldump -uroot -p123456 agentchat > backup.sql
```

### 6.2 数据库恢复
```bash
docker exec -i agentchat-mysql mysql -uroot -p123456 agentchat < backup.sql
```

### 6.3 向量库备份

ChromaDB 数据存储在容器内 /app/agentchat/data/chroma 目录（具体路径取决于配置）。建议将该目录挂载到宿主机，便于备份和持久化。
