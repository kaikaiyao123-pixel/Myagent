AgentChat 公网部署清单

两条上公网路径，按需选一。仓库已备齐两套脚本：deploy.sh（云服务器）与 start_tunnel.sh（内网穿透）。

方案 A · 云服务器（正式）

固定地址、长期可用。需一台公网服务器。

方案 B · 内网穿透（临时）

零服务器、本机直上公网。地址会过期。

方案 A — 云服务器标准部署

① 必须：一台云服务器（公网 IP、≥4GB 内存、≥20GB 磁盘、Docker 20.10+ 与 Compose V2）

② 必须：编辑 docker/.env（已存在，勿 cp 覆盖）

③ 必须（建议）：域名 + HTTPS

# 在服务器上执行 cd AgentChat-main/docker nano .env # 填 DASHSCOPE_API_KEY 与强口令 ./deploy.sh # 预检→生成密钥→渲染配置→构建→启动→验收 ./deploy.sh --verify # 只验收不重部署 ./deploy.sh --down # 停服（保留数据卷）
方案 A 必知坑： ① 冷启动首字延迟可达 ~90 秒（重资源懒初始化），部署完务必先用一个账号发一条消息"预热"； ② 首次启动后端要初始化数据库，若 5 个容器未全起，看 docker compose -f docker-compose.prod.yml logs； ③ 容器数据卷名为 agentchat-prod，与开发版隔离，勿混用。

方案 B — 内网穿透隧道（本机）

① 必须：本机服务已跑起来

② 必须：能出网 + 有 ssh 客户端

# 在本机执行 cd AgentChat-main/docker docker compose up -d ./start_tunnel.sh # serveo（默认） ./start_tunnel.sh pinggy # 或 pinggy # 公网地址打印并写入 tunnel_url.txt

验收口径（deploy.sh 已内置）：前端首页 200、/healthz 200、/api/v1/dialog/list 返回 401/403（说明反代贯通且鉴权生效）、/minio/agentchat/ 可达。
