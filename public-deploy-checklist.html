2. 系统初始化：Docker + 2G swap

① 登录服务器

两种方式：

  • 控制台网页终端：阿里云控制台 → 轻量应用服务器 → 实例 →「远程连接」→ 免客户端直接开终端。
  • 本地 SSH：终端执行 ssh root@你的公网IP（密码是购买时设置的；也可在控制台绑定 SSH 密钥后免密）。

在控制台实例详情页拿到公网 IP——后续部署和域名解析都要用它。

② 加 2G swap（关键）

登录后先装运行环境。重点：2核2G 必须先加 swap，否则构建阶段极易 OOM。

bash添加并持久化 swap
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
# 验证：free -h 应能看到 2.0Gi swap

③ 安装 Docker + Compose

bash安装 Docker 引擎与 Compose v2
# 官方一键脚本（Ubuntu）
curl -fsSL https://get.docker.com | sudo sh
# 让当前用户免 sudo 跑 docker（改完重新登录生效）
sudo usermod -aG docker $USER
# 确认版本
docker --version
docker compose version

④ 配置 Docker 镜像加速器（国内必做）

Docker 默认从 docker.io（Docker Hub）拉镜像，在中国大陆经常超时或不可达，直接报 dial tcp ... i/o timeout。必须在部署前给 Docker 配国内镜像源，否则第 5 节的 ./deploy.sh 构建必然卡死在拉取基础镜像（python / node / nginx / mysql / redis）。

方案 A（推荐，最快）：阿里云专属加速器。打开 https://cr.console.aliyun.com → 左侧「镜像工具」→「镜像加速器」，复制你的专属地址（形如 https://xxxxxx.mirror.aliyuncs.com），在服务器执行（把地址换成你自己的）：

bash阿里云专属镜像加速器（替换地址）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": ["https://xxxxxx.mirror.aliyuncs.com"]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A3 'Registry Mirrors'

方案 B（零注册，现在就能跑）：公用镜像源。不登录任何控制台，直接粘贴：

bash公用镜像加速器（无需注册）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://hub-mirror.c.163.com",
    "https://mirror.baidubce.com",
    "https://docker.m.daocloud.io"
  ]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -A5 'Registry Mirrors'

最后一行应能看到你配置的镜像地址，说明生效。配置后必须 restart docker 才会生效。

minio 镜像来自 quay.io，部分加速器不代理它。若部署时 minio 也超时，在 docker/ 目录下执行 sed -i 's#quay.io/minio/minio#minio/minio#' docker-compose.prod.yml 改用 Docker Hub 上的同名官方镜像即可（无害，标签一致）。
某个公用镜像源偶尔返回 502 / 404「not found」：这是公用镜像源抖动（如 docker.m.daocloud.io 返回 502、hub-mirror.c.163.com 等对个别镜像返回 404「not found」），不是你的问题。关键：镜像源返回 404「not found」时 Docker 不会自动换下一个源，所以必须把不行的源直接从列表里删掉（不能只排到最后），只留能用的；最稳是直接用方案 A 的阿里云专属加速器。若报 no such host（DNS 解析失败，如 lookup hub-mirror.c.163.com ... no such host），说明该源域名当前解析不了，直接换阿里云专属加速器；若所有源都 no such host，则是服务器 DNS 解析器问题，把 /etc/resolv.conf 的 nameserver 改为 223.5.5.5 / 8.8.8.8 即可。改完 systemctl restart docker 再重跑 bash ./deploy.sh，已拉取的层有缓存会续跑。

⑤ 确认 python3

bash确认 python3
python3 --version   # 一般系统已自带，需 >= 3.10
构建阶段（uv sync 拉 Python 包 + 下载 Chromium + 前端 vite 构建）内存峰值很高。2G 不加 swap 几乎必 OOM。若构建仍 OOM，临时把 swap 加到 3-4G，构建完再降回 2G。

3. 2核2G 四步调优（4G 机器可跳过）

执行本节前必须先完成第 5 节的 git clone：本节的调优脚本改的是克隆到服务器上的 docker/.env 与 docker-compose.prod.yml，文件不存在就无法改。且所有命令都必须在克隆下来的 docker/ 目录里执行（先 cd Myagent/docker）。

deploy.sh 在内存低于 3500MB 时只是告警、不会中止；真正会 exit 1 的只有 Docker/Compose/守护进程/python3 缺失，或 DASHSCOPE_API_KEY 为空。但 2G 要跑得稳，需改 4 处（均在项目 docker/ 目录）：

步骤 A：docker/.env 降 worker + 填密钥

envdocker/.env 关键项
# 必填：否则 deploy.sh 直接 exit 1
DASHSCOPE_API_KEY=sk-你的真实key

# 2核2G 只开 1 个 worker（默认值 2 会吃紧）
UVICORN_WORKERS=1

步骤 B：docker-compose.prod.yml 给 MySQL 限内存

把 mysql 服务的 image: mysql:8.0 下面加一行 command，把 MySQL 压到约 150MB：

yamlmysql 服务追加 command
  mysql:
    container_name: agentchat-mysql
    image: mysql:8.0
    # 2核2G 必加：限制 MySQL 内存占用
    command:
      - 'mysqld'
      - '--innodb-buffer-pool-size=64M'
      - '--performance-schema=OFF'
      - '--max-connections=50'

步骤 C：swap（已在第 2 步完成）

确认 free -h 能看到 2G swap。

步骤 D：构建仍 OOM 的兜底

  1. 临时把 swap 加到 3-4G 再构建，完成后降回 2G。
  2. 或在本机（配置更好的电脑）先 docker compose build 把镜像 docker save 传上服务器 docker load，服务器只 up 不 build。

一键调优脚本（粘贴即用，无需手动编辑）

在克隆下来的 docker/ 目录里执行下面这段即可：

bash2核2G 一键调优
# 必须在克隆仓库的 docker/ 目录下执行；否则明确报错退出
test -f docker-compose.prod.yml && test -f .env.prod.example || { echo "错误：请在克隆仓库的 docker/ 目录下执行本脚本（先 cd Myagent/docker）"; exit 1; }
cp -n .env.prod.example .env
# .env：worker 降为 1
sed -i 's/^UVICORN_WORKERS=.*/UVICORN_WORKERS=1/' .env
# 填入 DASHSCOPE key（把 sk-你的真实key 换成实际值，否则 deploy.sh 会 exit 1）
sed -i 's/^#\?DASHSCOPE_API_KEY=.*/DASHSCOPE_API_KEY=sk-你的真实key/' .env
# compose：给 mysql 加内存上限（幂等，重复执行不会重复加）
python3 - <<'PY'
p='docker-compose.prod.yml'
s=open(p).read()
inject="    command:\n      - 'mysqld'\n      - '--innodb-buffer-pool-size=64M'\n      - '--performance-schema=OFF'\n      - '--max-connections=50'\n"
seg=s.split('mysql:',1)[1].split('redis:',1)[0]
if 'command:' not in seg:
    s=s.replace("    image: mysql:8.0\n", "    image: mysql:8.0\n"+inject, 1)
    open(p,'w').write(s)
    print('MySQL 限内存 command 已添加')
else:
    print('MySQL command 已存在，跳过')
PY
脚本幂等；DASHSCOPE_API_KEY 必须换成你的真实 key，否则 ./deploy.sh 会 exit 1。改完直接 ./deploy.sh 即可。

复制示例文件并按需填写：

变量必填说明

5. 一键部署 AgentChat

把代码弄到服务器：先在你本机完成 git push（沙箱无法代推，见第 10 节），再在服务器克隆仓库：

bash服务器：克隆并部署
# 在【服务器】上执行
git clone https://github.com/kaikaiyao123-pixel/Myagent.git
cd Myagent/docker

# 首次部署：预检 -> 生成密钥 -> 渲染配置 -> 构建 -> 启动 -> 验收
./deploy.sh

# 仅做验收（不重建）
./deploy.sh --verify

# 停止全部服务
./deploy.sh --down

部署成功后，浏览器访问 http://服务器公网IP 即可看到站点。若需上线域名，继续第 6-8 节。

deploy.sh 的预检会检查 Docker/Compose/守护进程/python3，缺失即 exit 1；内存不足只是告警。若卡在 exit 1，优先看是不是 DASHSCOPE_API_KEY 没填、或 Docker 没装好。
若构建阶段卡在 load metadata for ... i/o timeout，这是 Docker Hub 在国内不可达，不是你的配置错——回到第 2 节 ④ 给 Docker 配镜像加速器后，再跑 bash ./deploy.sh。
构建很慢是正常的，别中断：2核2G + 重镜像（gcc/pandoc/CJK 字体 + Chromium + 前端 vite 构建）首次构建常需 20–40 分钟，其中 apt-get 装编译工具、npm run build 各可能耗 5–10 分钟。进度数字（如 (21/35)）在涨就说明在跑，不要 Ctrl-C、不要关终端（SSH 掉线也会杀掉构建）。建议用 tmux 跑部署，断线也不中断；若不慎中断，重新 bash ./deploy.sh 会靠 Docker 层缓存从断点续跑。

6. 购买域名

  • 渠道：阿里云万网 或 腾讯云 DNSPod。
  • 价格：.cn 首年约 20-30 元，.top 约 10 元，.com 稍贵（约 60-80 元/年）。学生展示站用 .cn 性价比高。
  • 一个域名可以挂多个网站：用子域名（如 api.yourdomain.cn、www.yourdomain.cn）A 记录指向同一公网 IP，由 Nginx 的 server_name 分流；或用子路径。
域名和服务器可以在不同厂商（如在阿里云买服务器、在腾讯云买域名），只要把域名 DNS 解析到服务器 IP 即可。

7. ICP 备案（大陆服务器必须）

  • 在中国大陆，服务器对外提供 Web 服务必须 ICP 备案；未备案的域名解析到大陆服务器会被阻断。
  • 一个域名备一次即可覆盖其下所有子站（www / api 等都不用单独备）。
  • 流程：在服务器厂商的备案系统（阿里云备案 / 腾讯云备案）提交资料 → 管局审核，通常 1-2 周。
  • 备案期间，域名不能指向未备案的服务器对外服务；可先用 IP 访问调试，备案通过后再绑域名。
若你买的是境外/中国香港服务器，则无需 ICP 备案，但国内访问延迟更高。学生展示站建议走大陆服务器 + 备案，访问体验好。

8. 绑定域名与 HTTPS

① 解析

在域名控制台添加 A 记录：@ 和 www 都指向服务器公网 IP。

② 开启 HTTPS（可选但建议）

  1. 免费证书：用 Cloudflare（泛域名证书，改 NS 接入）或 Let's Encrypt（certbot）。
  2. 修改 docker-compose.prod.yml 的 frontend 服务，取消 ports: - "443:443" 注释，并把 80 改为跳转。
  3. 在 nginx/nginx.prod.conf 中配置 443 监听与证书路径。
备案通过前，先只用 IP 访问调试；备案通过后再切到域名 + HTTPS。
